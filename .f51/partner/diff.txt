# BLUEPRINT: Audit Log System — Fluxo Auditável Completo

## Diagnóstico do sistema atual

```
START
  → orchestrator_primary ── classifica intent, quantifica risco
    → respond_blocked ── se needs_scope
    → auto_full_analysis ── 6 experts + F51 + neural + SDCA + RAG + IBKR
      → agent (Bob ReAct loop) ── decide tools, forma tese
        ⇄ tool_executor ── executa, retorna resultado
        → auto_execute_paper ── paper order IBKR
          → explanation ── formata resposta final
            → END
```

### GAPS CRÍTICOS:

1. **Bob não sabe quem produziu o quê** — O state é um saco de dados. Se o F51 disse BLOCK e o neural disse BUY, Bob não vê a procedência.

2. **Erros são lista plana** — `errors: ["f51_error", "sdca_blocked"]`. Não dá pra saber em qual nó, com qual input, em que timestamp.

3. **Sem rastreamento de decisão** — Bob decidiu BUY_CANDIDATE mas o expert fundamental disse SELL? Ninguém sabe. O override é invisível.

4. **Sem latência por nó** — Impossível otimizar. O expert macro_risk tá demorando 30s? Ninguém vê.

5. **Expert committee voto vs Bob voto** — O comitê votou 4 BULLISH, 2 BEARISH. Bob decidiu WAIT. Por quê? Sem trilha.

## SOLUÇÃO: SuperEzio Decision Trace (SDT)

Inspirado em: LangGraph trajectory checking + evidence-based audit + agent blame attribution.
Tudo local, JSONL append-only, zero dependência externa.

### 1. Data Model: `DecisionTrace`

```python
@dataclass
class DecisionTrace:
    """One decision point in the pipeline."""
    trace_id: str           # UUID
    run_id: str             # pipeline run
    session_id: str
    node: str               # "orchestrator", "expert.fundamental", "agent.bob"
    agent: str              # "bob_qwen_local", "deepseek_v4", "glm_5.2"
    timestamp: str          # ISO 8601
    latency_ms: float       # tempo de execução do nó
    input_summary: str      # resumo do input (até 200 chars)
    output_summary: str     # resumo do output (até 500 chars)
    decision: str           # "ALLOW" | "BLOCK" | "BUY" | "SELL" | "WAIT" | "BULLISH" | "BEARISH"
    confidence: float       # 0-1
    evidence_refs: list[str]  # ["f51_verdict.passed", "expert.fundamental.bullish"]
    errors: list[str]       # erros neste nó
    overrides: str | None   # se este nó discordou de outro
```

### 2. Tabela: `decision_traces` (SQLite no investor.db)

```sql
CREATE TABLE IF NOT EXISTS decision_traces (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    trace_id TEXT NOT NULL,
    run_id TEXT NOT NULL,
    session_id TEXT,
    node TEXT NOT NULL,
    agent TEXT NOT NULL,
    timestamp TEXT NOT NULL,
    latency_ms REAL,
    decision TEXT,
    confidence REAL,
    evidence_refs TEXT,     -- JSON array
    errors TEXT,            -- JSON array
    overrides TEXT,         -- JSON: {"overridden_node": "...", "reason": "..."}
    input_summary TEXT,
    output_summary TEXT
);
CREATE INDEX idx_traces_run ON decision_traces(run_id);
CREATE INDEX idx_traces_node ON decision_traces(node);
CREATE INDEX idx_traces_agent ON decision_traces(agent);
```

### 3. Módulo: `src/core/audit/decision_trace.py`

Classe `DecisionTraceLogger`:
- `start_node(node, agent, run_id, session_id, input_summary)` → trace_id
- `end_node(trace_id, decision, confidence, output_summary, evidence_refs, overrides, errors, latency_ms)`
- `get_run_traces(run_id)` → lista ordenada por timestamp
- `get_blame_report(run_id)` → análise de quem errou
- `get_agent_stats(agent, days=7)` → taxa de erro, latência média, confiança média

### 4. Blame Report Format

```

## Pipeline Flow (com latência)
1. orchestrator_primary (qwen_local) — 234ms
   → Rota: market_scan, Intent: buscar_oportunidade, Conf: 0.92

   → 5 candidates, 12 rejected

```

### 5. Integração — cada nó do pipeline

Adicionar 3 linhas em CADA nó:

```python
from core.audit.decision_trace import get_trace_logger
tracer = get_trace_logger()
trace_id = tracer.start_node("orchestrator_primary", "qwen_local", run_id, session_id, message[:200])
# ... executa o nó ...
tracer.end_node(trace_id, decision=route, confidence=intent_confidence, 
                output_summary=plan_summary, evidence_refs=["regex_parser", "ceo_model"],
                errors=node_errors, latency_ms=elapsed_ms)
```

### 6. Endpoint de auditoria

`GET /health/trace/{run_id}` → JSON com blame report
`GET /health/trace/agent/{agent}/stats` → estatísticas do agente

## Implementação — 3 fases

### Fase A: Core (src/core/audit/decision_trace.py)
- DecisionTraceLogger com start_node/end_node
- Tabela decision_traces no investor.db
- get_run_traces(), get_blame_report(), get_agent_stats()
- Testes: test_trace_logger.py (8 testes)

### Fase B: Integração nos nós
- Adicionar tracer em: orchestrator, collector, cada expert, f51, sdca, neural, rag, agent (Bob), tool_executor
- 2 linhas por nó (start + end)
- Testes: verificar que cada nó gera trace

### Fase C: API + Visualização
- GET /health/trace/{run_id} — blame report JSON
- Health details inclui agent_stats
- Script: scripts/trace_viewer.py — blame report no terminal

## Regras
- Append-only, nunca apagar trace
- Tudo local, zero SaaS (sem LangSmith)
- Thread-safe (lock no write)
- Performance: < 1ms overhead por trace
- Formato: mesmo padrão do conversation_memory.jsonl
