1. VISÃO GERAL E MISSÃO DO SISTEMA
--------------------------------------------------------------------------------
O SuperEzio é uma plataforma local-first de inteligência e análise financeira
estruturada sob os princípios de previsibilidade operacional da F51 Labs. Sua
missão é entregar análises de risco sistêmico, estruturação de portfólios e
processamento de sinais em tempo real, combinando modelos determinísticos e a
flexibilidade cognitiva de um Large Language Model (LLM) atuando como CEO.
Tudo isso é executado localmente para garantir total privacidade de dados e
zero custo de infraestrutura cloud com LLMs.

2. ARQUITETURA DE MICROSSERVIÇOS E FLUXO DE DADOS
--------------------------------------------------------------------------------
A plataforma é organizada em duas instâncias de runtime locais principais:

  * CEO llama.cpp Server (:8082):
    Executa o modelo unificado de intenção e tomador de decisão final:
    SuperEzio CEO+Intent Merged Qwen3.6-35B-A3B Q4_K_M GGUF via llama-server.
    Exprime compatibilidade completa com a API da OpenAI.

  * FastAPI Agent Server (:8002):
    Gateway de integração, orquestrador de pipeline de dados e servidor do
    frontend embutido ChatGPT-style (HTML+CSS+JS inline).

Fluxo simplificado de uma análise:
  [Usuário/UI] -> [FastAPI :8002]
               -> [Orchestrator Node (Intent & Routing)]
               -> [Professional Data Collector (DataHub)]
               -> [CEO Agent Loop (Qwen3.6 local :8082 via ReAct)]
               -> [F51 Verdict Engine / PennyLab / Crisis Experts]
               -> [Streaming NDJSON / SSE] -> [Resposta Final na UI]

3. PIPELINE DE DECISÃO E ORQUESTRAÇÃO (LANGGRAPH)
--------------------------------------------------------------------------------
A orquestração do fluxo de execução de agentes é feita via LangGraph v1.0.5
(Pipeline v4). Ao invés de delegar o fluxo de controle de forma livre a agentes
autônomos que poderiam gerar loops infinitos ou comportamento imprevisível,
o SuperEzio impõe um grafo com nós acíclicos estritos:
  - `orchestrator_primary`: Determina a intenção do usuário e faz o roteamento.
  - `node_collector`: Consolida dados do mercado financeiro em tempo real.
  - `node_agent`: Instancia o loop ReAct do CEO Bob (Qwen3.6), permitindo a
    chamada a ferramentas matemáticas e analíticas, ou resolve a análise via
    caminho determinístico antes de chamar o modelo de linguagem.

4. IP MATEMÁTICA E MODELOS DE CRISE (src/experts/crisis/)
--------------------------------------------------------------------------------
A grande propriedade intelectual e diferencial quantitativo do SuperEzio está
no desenvolvimento em Numpy e Math puro de algoritmos clássicos de finanças
quantitativas e risco sistêmico. Sem o uso de frameworks estatísticos pesados
(como statsmodels ou scikit-learn nos solvers de produção), o código é leve,
altamente otimizado e portável para C++, Rust ou CUDA.

As joias matemáticas do sistema incluem:
  
  A. Growth-at-Risk Solver (growth_at_risk.py):
     Estima o pior cenário (percentil 5%) para crescimento macroeconômico. A
     regressão quantílica é otimizada por um algoritmo próprio de Mínimos
     Quadrados Iterativamente Reponderados (IRLS - Iteratively Reweighted Least
     Squares):
       beta^(k+1) = (X' W^(k) X)^(-1) X' W^(k) y
     onde a matriz de pesos diagonais W é reponderada a cada iteração com base
     na função de perda assimétrica (check function) do quantil escolhido.

  B. LPPLS Bubble Fit (lppls_bubble.py):
     Calibração do modelo Log-Periodic Power Law (LPPLS) de Didier Sornette para
     detecção de bolhas financeiras e crash iminente. Para contornar a
     instabilidade do ajuste não-linear clássico, o SuperEzio lineariza a
     equação reduzindo os 7 parâmetros originais. O sistema realiza um grid
     search sobre as variáveis não-lineares físicas (tempo crítico tc, expoente
     m, frequência w) e resolve os coeficientes lineares instantaneamente por
     Mínimos Quadrados Ordinários (np.linalg.lstsq) em O(1), aplicando também
     uma penalização termodinâmica se B > 0.

  C. Contágio de Redes e DebtRank-lite (network_contagion.py):
     Simulação de propagação de choques sistêmicos e correlação em múltiplos
     horizontes temporais com suavização EWMA (Média Móvel Exponencialmente
     Ponderada). O algoritmo calcula a matriz de adjacência e propaga choques
     de volatilidade iterativamente pela rede baseando-se no modelo de
     contágio DebtRank de Battiston et al.

  D. Hawkes Process Stress (hawkes_stress.py):
     Processos autoexcitáveis de pontos com decaimento exponencial de memória
     longa para modelar o clustering de pânicos e crashes no mercado:
       lambda(t) = mu + sum_{ti < t} (alpha * exp(-beta * (t - ti)))
     Identifica se volatilidades recentes representam tremores estruturais ou
     ruído passageiro.

5. ENGINE DE VEREDICTO F51 E COLETORES (DATAHUB)
--------------------------------------------------------------------------------
  * PennyLab Experts (src/experts/pennylab/):
    Quatro modelos específicos de scoring (whale, pump, trap, liquidity) que
    avaliam microcaps e ativos de alto risco em uma escala normalizada de 0 a 1.

  * DataHub & Providers:
    O coletor multi-fonte unificado distribui chamadas de API com controle de
    taxa de requisição estrito para evitar estouro de limites (rate limits). Ele
    integra em cascata: Finnhub -> Twelve Data -> yfinance -> Alpha Vantage ->
    Stooq (delayed keyless como fallback final).

6. PIPELINE DE TESTES E ESTRATÉGIA DE ZERO-GARBAGE-RUNTIME
--------------------------------------------------------------------------------
O repositório é controlado por uma rígida política de qualidade definida no
script master `scripts/verify_zero_garbage_runtime.ps1`.
Este script executa:
  1. Secret Leak Guard: Bloqueia chaves de API ou segredos acidentais.
  2. Placeholder Check: Verifica se o `.env.example` está atualizado.
  3. Boot-Smoke Check: Testa a importação estática de todos os entrypoints.
  4. Suíte de Contratos e Integração: Executa mais de 160 testes unitários e de
     contrato.
  5. Testes de Smoke de Interface: Executa scripts com Playwright
     (browser_smoke.py) contra a UI real para verificar o comportamento do chat,
     renderização de gráficos financeiros e telemetria SSE.
